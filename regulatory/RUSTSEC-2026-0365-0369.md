## Aplicabilidad al core y brechas

La base examinada no tiene `Cargo.toml`, `Cargo.lock`, `.rs` ni Dockerfile de producto. No hay prueba de que use `zip`, `negentropy`, `pest_grammars` o Tokio en un artefacto construido. Para cada componente se requiere versión, features, OS, API utilizada, procedencia del input, identidad y permisos del proceso, entidad/celda y digest del artefacto. Incluir herramientas del proveedor y del operador, importador inicial y builder. Si no se admiten ZIP o no se usa reconciliación `negentropy`, registrar el no alcance con fundamento; no incorporar esas dependencias para justificar el análisis.

## Implicación tecnológica verificada

La documentación de [Tokio `spawn_blocking`](https://docs.rs/tokio/1.53.3/tokio/task/fn.spawn_blocking.html), consultada mediante `latest` que mostraba **1.53.3**, explica que una tarea bloqueante ya iniciada no se cancela mediante `abort`; el timeout de apagado deja de esperar, pero no la detiene. Para tareas CPU recomienda limitar concurrencia mediante semáforo u otro mecanismo. Es contexto de ingeniería, no una release nueva del 17/10 ni una selección de librería de Bank.

**Alternativas para una futura decisión:** parsing dentro del proceso con librería corregida, validación previa y presupuesto cooperativo, o proceso supervisado con límites cuando sea necesario contener aborto/hacer efectivo un corte de ejecución. La segunda opción agrega IPC, ciclo de vida, observabilidad y costo. Corresponde evaluar el escenario con ADR-03/06/07/08; aquí no se adopta una topología nueva ni se afirma que una tarea asíncrona sea un sandbox.

## Criterios y evidencia

Casos propuestos con entradas sintéticas: conteo incoherente frente al tamaño real, JSON profundamente anidado, entrada ZIP con permisos privilegiados, enlace cuyo destino sale del staging, trabajo que excede presupuesto y reinicio tras rechazo. Medir consumo/terminación efectiva, aislamiento entre dos celdas, ausencia de archivos externos y ausencia de publicación financiera/efectos externos del lote rechazado. Fijar límites según formatos/carga del operador y oráculo independiente; no inventar valores universales.

**Realizado:** consulta/lectura de fichas y registros, comparación de huellas, lectura de Tokio y contraste documental de IDs. **No realizado:** instalación de paquetes, `cargo audit`, construcción, extracción de archivos maliciosos, explotación, escaneo ni ensayos de producto. Las propuestas esperan implementación, medición y revisión competente.
